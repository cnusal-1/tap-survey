수집 창구 만들기

조사자 여럿이 올린 자료를 한곳에 모으는 창구를 만든다. 한 번 만들면 끝이고, 그 뒤로 조사자는 앱에서 «데이터 보내기» 를 누르기만 하면 된다. 암구호도 계정도 없다.

약 10분 구글 계정 1개 (담당자만) 비용 없음 조사자는 누르기만

왜 이렇게 하나 — 조사자에게 토큰을 주면 안 되는 이유

저장소 쓰기 토큰은 그 저장소 전체에 대한 권한이다. 받은 사람은 남의 조사 자료를 지우거나 덮어쓸 수 있고, 사람이 바뀌면 회수할 방법이 마땅치 않다. 열 명에게 나눠 주면 열 개의 열쇠가 돌아다니는 셈이다.

창구를 두면 자격증명은 창구 안에만 있다. 앱에는 «여기로 보내라» 는 주소만 박힌다. 그 주소로는 올리는 것만 되고 읽기도 삭제도 안 되므로, 주소가 새어도 남의 자료를 가져갈 수 없다.

암구호는 두지 않는다. 조사자에게 외울 것을 하나 더 주면 현장에서 «비밀번호가 뭐였죠» 로 조사가 멈춘다. 대신 창구 쪽에 넷을 두었다 — 이름 검사(조사 파일 형식이 아니면 거부), 크기 제한(20 MB), 하루 상한(600 파일), 차단 스위치. 조사자는 이 넷을 전혀 느끼지 않는다.

만들기

1

새 프로젝트를 연다

script.google.com 에 담당자 구글 계정으로 들어가 새 프로젝트 를 누른다.

«제목 없는 프로젝트» 를 눌러 이름을 두들김 조사 수집 정도로 바꿔 둔다. 나중에 찾기 쉬워진다.

2

코드를 붙여넣는다

가운데 편집기에 function myFunction() { } 이 들어 있다. 전부 지우고 아래 코드를 통째로 붙여넣는다.

collector.gs
/**
 * 두들김 조사 — 수집 창구 (Google Apps Script)
 *
 * 조사자는 앱에서 «수집 서버로 보내기» 를 누르기만 한다. 암구호도 계정도 토큰도
 * 없다. 담당자가 이 창구를 한 번 만들고 주소를 앱에 박아 두면 끝이다.
 *
 * 암구호를 없앤 대신 아래 넷으로 막는다. 어느 것도 조사자를 귀찮게 하지 않는다.
 *   1) 이름 검사   조사 파일 형식이 아닌 것은 받지 않는다
 *   2) 크기 제한   파일 하나 20 MB
 *   3) 하루 상한   하루 600 파일 (조사 60건쯤). 넘으면 그날은 닫힌다
 *   4) 차단 스위치 OPEN 을 false 로 두면 즉시 닫힌다
 * 모든 수신은 조사 폴더의 _수신기록.csv 에 남는다.
 *
 * ── 만드는 법 ──────────────────────────────────────────────────
 *   자세한 안내: https://cnusal-1.github.io/tap-survey/collector-guide.html
 *
 * 1. script.google.com → 새 프로젝트
 * 2. 이 파일 내용을 통째로 붙여넣는다
 * 3. FOLDER 를 결과를 담을 구글 드라이브 폴더 ID 로 바꾼다.
 *    비워 두면 «두들김 조사» 폴더를 내 드라이브에 자동으로 만든다
 * 4. 배포 → 새 배포 → 유형 «웹 앱»
 *      실행 계정 : 나
 *      액세스 권한: 모든 사용자          ← 조사자가 로그인하지 않아도 되게
 *    권한 승인을 한 번 요구한다. 승인한다
 * 5. 나오는 /exec 주소를 앱의 COLLECT_URL 에 박아 넣는다 (index.html 위쪽)
 *
 * ── 알아 둘 것 ─────────────────────────────────────────────────
 * · 주소를 아는 사람은 누구나 올릴 수 있다. 그래서 위의 넷이 있다
 * · 이 창구는 «쓰기만» 한다. 읽기도 삭제도 없다. 주소가 새어도 남의 조사
 *   자료를 가져갈 수는 없다
 * · 코드를 고치면 «배포 → 배포 관리 → 편집 → 새 버전» 을 해야 반영된다
 */

var FOLDER    = "";      // 구글 드라이브 폴더 ID. 비우면 자동 생성
var OPEN      = true;    // false 로 두면 창구를 닫는다
var MAXBYTES  = 20 * 1024 * 1024;   // 파일 하나 상한
var DAILYCAP  = 600;                // 하루에 받을 파일 수 상한
var SECRET    = "";      // 비워 두면 암구호를 묻지 않는다. 쓰려면 값을 넣는다

/* 받을 파일 이름 — 앱이 만드는 형식만 통과시킨다
   예) 20260902_1430-만경강교-P22-코핑_하면(동쪽)-T001.wav              */
var NAME_OK = /^\d{8}_\d{4}-.+\.(csv|jpg|jpeg|png|wav)$/i;

function doPost(e) {
  try {
    if (!OPEN) return reply({ ok: false, error: "창구가 닫혀 있다. 담당자에게 문의하라" });
    if (!e || !e.postData || !e.postData.contents) return reply({ ok: false, error: "빈 요청" });

    var q = JSON.parse(e.postData.contents);

    if (SECRET && String(q.key || "") !== SECRET) return reply({ ok: false, error: "암구호 불일치" });
    if (!q.survey || !q.name || !q.data) return reply({ ok: false, error: "survey·name·data 가 필요하다" });

    var survey = String(q.survey).replace(/[\/\\:*?"<>|]/g, "_").slice(0, 120);
    var name   = String(q.name).replace(/[\/\\:*?"<>|]/g, "_").slice(0, 160);

    /* 1) 이름 검사 — 조사 파일이 아닌 것을 걸러낸다 */
    if (!NAME_OK.test(name)) return reply({ ok: false, error: "조사 파일 형식이 아니다: " + name });

    /* 2) 크기 제한 */
    var bytes = Utilities.base64Decode(q.data);
    if (bytes.length > MAXBYTES) {
      return reply({ ok: false, error: "파일이 너무 크다 (" + Math.round(bytes.length / 1048576) + " MB)" });
    }

    /* 3) 하루 상한 */
    var used = bump_();
    if (used > DAILYCAP) return reply({ ok: false, error: "오늘 받을 수 있는 양을 넘었다. 내일 다시 보내라" });

    var root = FOLDER ? DriveApp.getFolderById(FOLDER) : rootFolder_();
    var dir  = childFolder_(root, survey);

    var blob = Utilities.newBlob(bytes, q.type || "application/octet-stream", name);

    /* 같은 이름이 이미 있으면 덮어쓴다 — 통신이 끊겨 다시 보낸 경우다 */
    var old = dir.getFilesByName(name);
    while (old.hasNext()) old.next().setTrashed(true);

    var f = dir.createFile(blob);

    log_(dir, q, name, f.getSize());
    return reply({ ok: true, id: f.getId(), bytes: f.getSize(), todayUsed: used, dailyCap: DAILYCAP });

  } catch (err) {
    return reply({ ok: false, error: String(err && err.message || err) });
  }
}

/* 브라우저로 주소를 열었을 때 — 살아 있는지와 오늘 남은 양만 알려 준다 */
function doGet() {
  return reply({
    ok: true, service: "두들김 조사 수집 창구",
    open: OPEN, todayUsed: peek_(), dailyCap: DAILYCAP, note: "POST 로 보낸다"
  });
}

function reply(o) {
  return ContentService.createTextOutput(JSON.stringify(o))
    .setMimeType(ContentService.MimeType.JSON);
}

/* ---------- 하루 상한 ---------- */
function dayKey_() {
  return "cnt_" + Utilities.formatDate(new Date(), Session.getScriptTimeZone(), "yyyyMMdd");
}
function bump_() {
  var p = PropertiesService.getScriptProperties();
  var k = dayKey_();
  var lock = LockService.getScriptLock();
  try {
    lock.waitLock(5000);
    var n = parseInt(p.getProperty(k) || "0", 10) + 1;
    p.setProperty(k, String(n));
    return n;
  } catch (e) {
    return parseInt(p.getProperty(k) || "0", 10) + 1;   // 잠금 실패해도 업로드는 막지 않는다
  } finally {
    try { lock.releaseLock(); } catch (e) {}
  }
}
function peek_() {
  return parseInt(PropertiesService.getScriptProperties().getProperty(dayKey_()) || "0", 10);
}

/* ---------- 폴더 ---------- */
function rootFolder_() {
  var it = DriveApp.getFoldersByName("두들김 조사");
  return it.hasNext() ? it.next() : DriveApp.createFolder("두들김 조사");
}
function childFolder_(parent, name) {
  var it = parent.getFoldersByName(name);
  return it.hasNext() ? it.next() : parent.createFolder(name);
}

/* 조사 폴더마다 누가 언제 무엇을 올렸는지 한 줄씩 남긴다 */
function log_(dir, q, name, bytes) {
  try {
    var line = [
      new Date().toISOString(),
      q.inspector || "",
      q.bridge || "",
      name,
      bytes
    ].join(",") + "\n";
    var it = dir.getFilesByName("_수신기록.csv");
    if (it.hasNext()) {
      var f = it.next();
      f.setContent(f.getBlob().getDataAsString("UTF-8") + line);
    } else {
      dir.createFile("_수신기록.csv",
        "﻿수신시각,점검원,교량명,파일,바이트\n" + line, "text/csv");
    }
  } catch (e) { /* 기록 실패가 업로드를 막지는 않는다 */ }
}
3

설정을 확인한다 (대개 그대로 두면 된다)

코드 위쪽의 다섯 줄이 전부다. 손대지 않아도 동작한다.

var FOLDER   = "";                 // 비우면 «두들김 조사» 폴더를 자동 생성
var OPEN     = true;               // false 로 두면 창구를 즉시 닫는다
var MAXBYTES = 20 * 1024 * 1024;   // 파일 하나 20 MB
var DAILYCAP = 600;                // 하루 600 파일 (조사 60건쯤)
var SECRET   = "";                 // 비우면 암구호를 묻지 않는다
  • 특정 폴더에 모으고 싶으면 그 폴더를 드라이브에서 열었을 때 주소 끝에 붙는 ID 를 FOLDER 에 넣는다
  • 조사 인원이 많아 하루 600 파일로 모자라면 DAILYCAP 을 올린다
  • 굳이 암구호를 쓰겠다면 SECRET 에 값을 넣는다. 그러면 조사자가 앱의 «보낼 곳 바꾸기» 에서 그 값을 넣어야 한다

디스크 모양 저장 아이콘을 누른다.

4

웹 앱으로 배포한다

오른쪽 위 배포 → 새 배포. 왼쪽 톱니바퀴에서 웹 앱 을 고르고, 아래 둘을 반드시 이렇게 맞춘다.

왜 «모든 사용자» 인가 구글 계정 없이도 올릴 수 있게 하려는 것이다. 실행은 담당자 계정으로 되므로 파일은 담당자 드라이브에 쌓인다. 조사자가 담당자 드라이브를 들여다볼 수 있게 되는 것이 아니다.
5

«확인되지 않은 앱» 경고를 넘어간다

배포를 누르면 권한 승인을 한 번 요구한다. 여기서 대부분 막힌다.

  • 액세스 승인 → 계정 선택
  • «Google에서 확인하지 않은 앱입니다» 화면이 뜬다
  • 왼쪽 아래 고급 → 두들김 조사 수집(안전하지 않음)으로 이동
  • 허용
놀라지 말 것 내가 방금 쓴 스크립트라 구글의 심사를 받지 않았다는 뜻이지, 위험하다는 뜻이 아니다. 요구하는 권한은 내 드라이브에 파일을 만드는 것 하나다.
6

주소를 받는다

승인이 끝나면 웹 앱 URL 이 나온다. /exec 로 끝난다.

https://script.google.com/macros/s/AKfycb…아주긴글자…/exec

이 주소를 복사해 둔다. 창을 닫아 잃어버려도 배포 → 배포 관리 에서 다시 볼 수 있다.

그 주소를 브라우저에 그대로 붙여넣어 열면 {"ok":true,…} 가 나온다. 이러면 살아 있는 것이다. «스크립트를 실행할 권한이 없습니다» 가 나오면 4단계의 액세스 권한이 «모든 사용자» 가 아닌 것이다.

7

주소를 앱에 박아 넣는다

이 단계가 «누르기만 하면 되게» 만드는 부분이다. 앱 저장소의 index.html 을 열어 위쪽의 이 줄을 찾는다.

const COLLECT_URL = "";
const COLLECT_NAME = "담당자 수집 창구";

따옴표 사이에 6단계의 주소를 넣고, 이름은 팀에서 부르는 대로 바꾼다.

const COLLECT_URL = "https://script.google.com/macros/s/AKfycb…/exec";
const COLLECT_NAME = "구조안전팀 수집함";

깃허브에서 바로 고칠 수 있다 — 파일을 열고 연필 아이콘 Edit → 고치고 Commit changes. 1~2분 뒤 반영된다.

주소가 공개된다 앱 저장소가 공개면 이 주소도 공개된다. 그래서 창구에 이름 검사·크기 제한·하루 상한·차단 스위치를 둔 것이다. 그래도 마음에 걸리면 앱 저장소를 비공개로 두고 사내 서버에 올리거나, SECRET 을 쓴다.
8

앱에서 한 번 보내 본다

휴대폰에서 앱 을 열고 아무 사진이나 찍어 타점 하나만 기록한 뒤, 저장 화면에서 데이터 보내기 를 누른다. 그것뿐이다.

내 드라이브의 «두들김 조사» 폴더에 조사 이름으로 폴더가 생기고 파일이 들어와 있으면 끝이다. 폴더 안 _수신기록.csv 에 누가 언제 무엇을 올렸는지 한 줄 남는다.

조사자에게 줄 것

앱 주소 하나면 된다.

앱 주소
https://cnusal-1.github.io/tap-survey/

보낼 곳은 앱에 박혀 있다. 조사자는 조사를 마치고 «데이터 보내기» 를 누르기만 한다. 외울 것도, 넣을 것도 없다.

앱을 홈 화면에 추가해 두라고 함께 일러 준다 — 아이폰 Safari 공유 ↑ → 홈 화면에 추가, 안드로이드 Chrome ⋮ → 홈 화면에 추가. 주소창 없는 전체화면으로 열려 현장에서 훨씬 낫다.

막혔을 때

증상원인과 조치
보낼 곳이 없다앱의 COLLECT_URL 이 비어 있다. 7단계를 하지 않았거나 반영 전이다. 급하면 조사자가 앱의 «보낼 곳 바꾸기» 에 주소를 직접 넣어도 된다
조사 파일 형식이 아니다창구의 이름 검사에 걸렸다. 앱이 만든 파일이 맞다면 담당자에게 알린다 — NAME_OK 규칙을 넓히면 된다
오늘 받을 수 있는 양을 넘었다하루 상한(600 파일)에 닿았다. DAILYCAP 을 올리고 새 버전으로 배포한다. 조사 기록은 기기에 남아 있으니 잃지 않는다
연결하지 못했다통신이 안 되는 곳이다. 기록은 기기에 남아 있다 — 통신되는 곳에서 앱을 열어 «조사 종료 및 저장» 으로 돌아가 다시 누르면 된다
권한이 없습니다액세스 권한이 «모든 사용자» 가 아니다. 배포 관리에서 고친다
창구가 닫혀 있다OPEN 이 false 다. 담당자가 일부러 닫은 것이다
코드를 고쳤는데 그대로다저장만으로는 반영되지 않는다. 배포 → 배포 관리 → 연필 → 버전 새 버전 → 배포. 주소는 그대로 유지된다
파일이 반만 왔다중간에 끊긴 것이다. 다시 보내면 같은 이름을 덮어쓰므로 중복이 생기지 않는다
드라이브가 꽉 찼다조사 한 건이 10 MB 안팎이다. 무료 15 GB 면 1,000건 정도. 넘으면 오래된 조사를 다른 곳으로 옮긴다

알아 둘 것

주소를 아는 사람은 올릴 수 있다암구호를 없앤 대신 이름 검사·크기 제한·하루 상한·차단 스위치를 두었다. 어느 것도 완벽한 방어가 아니다 — 조사 폴더마다 남는 _수신기록.csv 로 담당자가 확인하는 것이 마지막 장치다
